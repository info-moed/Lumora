# x265 (HEVC)

**Documented version:** 4.3+1-e9b8812 · **Codec:** HEVC · **License:** GPL-2.0 (commercial license available from MulticoreWare) · **Homepage:** <https://bitbucket.org/multicoreware/x265_git> · **Homebrew:** [`x265`](https://formulae.brew.sh/formula/x265)

x265 is the reference open-source HEVC/H.265 encoder from MulticoreWare. It is mature and very configurable, encodes 8, 10 and 12-bit with 4:0:0/4:2:0/4:2:2/4:4:4, and has first-class HDR10, HLG and Dolby Vision signaling, and its output plays on almost every modern device at 10-bit. Weaknesses: it is far slower than hardware HEVC, its defaults are tuned for low bitrates (SAO and psy settings often need adjusting for high-fidelity work), its efficiency trails modern AV1 and VVC encoders, and this build lacks SCC, alpha and MV-HEVC (those options are rejected). HDR10+ works only in 10-bit encodes (see the hdr section).

**Bit depths:** 8, 10, 12 · **Chroma:** 4:0:0, 4:2:0, 4:2:2, 4:4:4

Machine-readable data: [`data/x265.json`](data/x265.json). Every option below is listed in the installed tool's own help; descriptions are written for this reference, and each recommendation links to its source.

## HDR

For HDR10: encode 10-bit 4:2:0 (`-D` 10, `--profile` main10), signal BT.2020 primaries, PQ transfer and BT.2020 non-constant matrix (`--colorprim` bt2020 `--transfer` smpte2084 `--colormatrix` bt2020nc, `--range` limited), and copy the source's static metadata with `--master-display` and `--max-cll`. Those two imply `--hdr10`, which in turn turns on `--repeat-headers`. Add `--hdr10-opt` for PQ-aware QP (10-bit 4:2:0 only). For HLG: same primaries/matrix with `--transfer` arib-std-b67 and no mastering metadata needed. `--video-signal-type-preset` BT2100_PQ_YCC[:volume] sets the whole VUI in one go. 12-bit PQ (Main12) is valid HEVC for archival masters, but it is not HDR10 and most consumer decoders can't play it. Dolby Vision (`--dolby-vision-profile` plus `--dolby-vision-rpu`) needs 10-bit 4:2:0 and VBV; the help lists profiles 5, 8.1 and 8.2, and this build also accepts 8.4 (verified). HDR10+: `--dhdr10-info` <json> is not in the help, but in this Homebrew build it works for 10-bit encodes only (the 10-bit library is compiled with HDR10_PLUS; verified with a hdr10plus_tool JSON). At 8-bit and 12-bit it is ignored with a warning, so for those depths inject the metadata afterwards with hdr10plus_tool.

**Flags involved:** `--output-depth`, `--profile`, `--range`, `--colorprim`, `--transfer`, `--colormatrix`, `--chromaloc`, `--master-display`, `--max-cll`, `--cll`, `--hdr10`, `--hdr10-opt`, `--repeat-headers`, `--video-signal-type-preset`, `--atc-sei`, `--pic-struct`, `--dolby-vision-profile`, `--dolby-vision-rpu`, `--vbv-maxrate`, `--vbv-bufsize`, `--uhd-bd`, `--aud`, `--hrd`

**Example (HDR10):**

```bash
x265 --input src.y4m --y4m --output out.hevc --preset slow --crf 18 --output-depth 10 --profile main10 --range limited --colorprim bt2020 --transfer smpte2084 --colormatrix bt2020nc --master-display "G(13250,34500)B(7500,3000)R(34000,16000)WP(15635,16450)L(10000000,50)" --max-cll "1000,400" --hdr10 --hdr10-opt --repeat-headers
```

**Pitfalls:**

- `--master-display` order is G, B, R, WP, then L(max,min). Chromaticity is in 0.00002 units (ffprobe's x/50000 numerator); luminance is in 0.0001 nits (1000 nits = 10000000). Swapping max and min is a common mistake.
- `--hdr10-opt` does nothing at 12-bit or without BT.2020/PQ signaling: x265 4.3 logs an error ('Recommended Settings for HDR10-opt ...'), disables it and keeps encoding with exit code 0, so check the log (verified on this build).
- HDR10+ depends on bit depth in this Homebrew build. `--dhdr10-info` is not in the help, yet a 10-bit encode (`-D` 10) accepts it and writes SMPTE 2094-40 SEI on every frame; the 8-bit and 12-bit libraries print '`--dhdr10-info` disabled. Enable HDR10_PLUS in cmake.' and ignore it (all verified on 4.3+1). A malformed JSON makes the 10-bit encode abort. For 8/12-bit, or to add metadata later, use `hdr10plus_tool inject -i out.hevc -j metadata.json -o out_hdr10plus.hevc`.
- Dolby Vision through x265 is Main10 only (12-bit is refused: "profile - 5, profile - 8.1, profile - 8.2 and profile - 8.4 are Main10 only") and needs `--vbv-bufsize`/--vbv-maxrate (verified error messages); profile 8.1 also needs `--master-display`. A 12-bit archival encode cannot carry DV.
- The RPU or HDR10+ JSON must match the encoded frames one-to-one. Trimming, `--seek`/--frames, frame-rate conversion, interpolation or `--frame-dup` break the match. A frame-interpolating pipeline needs regenerated metadata (general practice; not spelled out in the tool READMEs read).
- x265 only signals color; it never converts. The input must already be PQ/HLG BT.2020 at the right range.
- `--max-cll` 0,0 means 'unknown'. After grading or tone changes the source's MaxCLL/MaxFALL may no longer be correct.
- `--hdr-opt` is the deprecated old name of `--hdr10-opt`; older guides (including the codecalamity article) still show hdr-opt=1.
- Through ffmpeg, pass HDR settings in -x265-params with ':' separators and use commas inside values (max-cll=1000,400). The HDR article warns that ffmpeg did not carry HDR metadata over automatically in the versions it tested; verify the output with ffprobe or MediaInfo. HDR10+ also passes through this way (dhdr10-info=metadata.json inside -x265-params with -pix_fmt yuv420p10le; verified with ffmpeg's libx265 on this machine).
- Pasted curly quotes break the `--master-display` string; some shells also need the parentheses quoted.
- `--video-signal-type-preset` overrides individual VUI flags; its BT2020_YCC_NCL row in the help lists colormatrix bt709, which looks like a help-text mistake.
- `--tune` grain disables AQ; `--hdr10-opt` is documented to work best with AQ enabled.

## Presets

| Preset | Speed | Notes |
|---|---|---|
| ultrafast | fastest | CTU 32, min CU 16, 1 ref, dia search, subme 0, no SAO, no AQ, no weighted prediction, rd 2, scene cut off. Largest files; the wiki calls it inconsistent. Previews only. |
| superfast | very fast | Like ultrafast but min CU 8, hex search, scene cut on, sign hiding on. Previews and throwaway encodes. |
| veryfast | very fast | CTU 64, 2 refs, AQ mode 2, SAO and weightp on, 15-frame lookahead. Quick drafts. |
| faster | fast | As veryfast with subme 2. Real-time-ish encodes on strong CPUs. Lumora's fastest HEVC rung (measured about 1.6x medium's speed, 7% larger). |
| fast | fast | 3 refs; early skip off. Not on Lumora's ladder: on an M3 Max it was slower than medium (CPU time) and about 3% larger. The anime guide advises against fast for anime. |
| medium | moderate (default) | Default: 3 refs, hex, subme 2, b-adapt 2, rd 3, 20-frame lookahead, b-intra on. psy-rdoq has no effect here (rdoq-level 0). |
| slow | slow | star search, subme 3, 4 refs, rect on, rd 4, rdoq-level 2, psy-rdoq 1.0, 25-frame lookahead. Lumora's default rung; the anime guide's recommended preset; a common good balance. |
| slower | very slow | 8 B-frames, 5 refs, rect+amp, rd 6, TU depth 3, weightb, 40-frame lookahead, limit-tu 4. A common archival choice. |
| veryslow | extremely slow | As slower but max-merge 5, no ref/mode limits, no limit-tu. One guide's archival starting point; small gains over slower. |
| placebo | slowest | merange 92, subme 5, TU depth 4, 60-frame lookahead, tskip on, rskip off. The wiki says it is slightly worse than veryslow in practice; not worth the time. |

## Rate control

| Mode | Flags | Notes |
|---|---|---|
| CRF (constant rate factor) | --crf <0-51> | Default (28). Constant perceived quality, variable size. Best choice for archives and files. Lower = better; about +6 halves size (wiki). |
| Capped CRF | --crf N --vbv-maxrate K --vbv-bufsize K [--crf-max/--crf-min] | CRF with a peak-rate cap for streaming or device limits. VBV makes output non-deterministic unless `--const-vbv`. Required shape for Dolby Vision encodes. |
| CQP (constant QP) | --qp N | Fixed quantizer with I/P/B offsets from `--ipratio`/--pbratio. Wastes bits versus CRF; for testing only. QP 0 is not lossless. |
| ABR (one-pass average bitrate) | --bitrate kbps | Hits an average bitrate without lookahead knowledge; less efficient and consistent than CRF (wiki). |
| Two-pass VBR | --pass 1 --bitrate kbps --stats f.log, then --pass 2 (same options) | Accurate file-size targeting. `--slow-firstpass` (default) keeps pass 1 accurate; `--multi-pass-opt-analysis`/-distortion can refine pass 2. |
| CBR | --bitrate K --vbv-maxrate K --vbv-bufsize B [--strict-cbr] [--hrd] | Constant bitrate for broadcast/streaming; `--strict-cbr` keeps the average within about 5%. |
| Segment-based RC | --sbrc (with --crf and VBV) | Experimental capped-CRF that plans per keyframe segment; forces closed, fixed GOPs. |
| Lossless | --lossless | Bit-exact; rate control ignored. The wiki recommends x264 for lossless instead because it is much faster. |

## Recipes

### HEVC 12-bit archival, live action

**Goal:** archive · **Content:** live action

```bash
--preset slower --crf 16 --output-depth 12 --profile main12 --no-sao --deblock -2:-2 --no-strong-intra-smoothing --ref 6 --rc-lookahead 60 --bframes 8 --aq-mode 2 --psy-rd 2.0 --psy-rdoq 1.0
```

Slower preset with low CRF; SAO off and gentler deblocking keep fine texture at low CRF; intra smoothing off for sharp sources; deeper references and lookahead. Keeps the default AQ mode and cutree where the guides disagree.

Sources: [source](https://silentaperture.gitlab.io/mdbook-guide/encoding/x265.html), [source](https://codecs.wiki/docs/encoders/x265), [source](https://x265.readthedocs.io/en/master/presets.html)

### Anime, 10-bit, high quality

**Goal:** archive · **Content:** anime

```bash
--preset slow --crf 19 --output-depth 10 --profile main10 --limit-sao --bframes 8 --psy-rd 1 --aq-mode 3
```

The anime guide's high-quality line: dark-scene AQ against banding, limited SAO near CRF 18-20, and 8 B-frames for a few percent saving.

Sources: [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/)

### Anime, 12-bit archival (Lumora-style)

**Goal:** archive · **Content:** anime

```bash
--preset slower --crf 16 --output-depth 12 --profile main12 --tune animation --limit-sao --deblock -1:-1 --aq-mode 3 --bframes 8 --ref 6 --rc-lookahead 60
```

Combines tune animation (low psy-rd and aq-strength) with gentler deblocking and limited SAO. Note `--tune` animation is accepted but not in the help list. The anime guide found 10-bit better than 12-bit at high CRF, so 12-bit is only worthwhile at low CRF.

Sources: [source](https://x265.readthedocs.io/en/master/presets.html), [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/), [source](https://codecs.wiki/docs/encoders/x265)

### Heavy film grain

**Goal:** archive · **Content:** heavy grain

```bash
--preset slow --crf 18 --output-depth 10 --tune grain
```

The grain tune keeps QP flat (rc-grain, qpstep 1, ipratio 1.1, pbratio 1.0), turns off AQ, cutree and SAO, and raises psy-rd/psy-rdoq so grain doesn't smear or pulse. The anime guide finds it too strong on slower presets; the manual alternative is psy-rdoq 2-3 with `--no-sao` and `--deblock` -2:-2.

Sources: [source](https://x265.readthedocs.io/en/master/presets.html), [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/), [source](https://silentaperture.gitlab.io/mdbook-guide/encoding/x265.html)

### HDR10, 10-bit (playable)

**Goal:** HDR · **Content:** live action

```bash
--preset slow --crf 18 --output-depth 10 --profile main10 --range limited --colorprim bt2020 --transfer smpte2084 --colormatrix bt2020nc --master-display "G(13250,34500)B(7500,3000)R(34000,16000)WP(15635,16450)L(10000000,50)" --max-cll "1000,400" --hdr10 --hdr10-opt --repeat-headers
```

Full HDR10 signaling with static metadata copied from the source; hdr10-opt applies PQ-aware QP at 10-bit. Replace master-display and max-cll with the source's values.

Sources: [source](https://x265.readthedocs.io/en/master/cli.html), [source](https://codecalamity.com/encoding-uhd-4k-hdr10-videos-with-ffmpeg/)

### HDR PQ, 12-bit archival master

**Goal:** archive · **Content:** HDR

```bash
--preset slower --crf 14 --output-depth 12 --profile main12 --range limited --colorprim bt2020 --transfer smpte2084 --colormatrix bt2020nc --master-display "<from source>" --max-cll "<from source>" --hdr10 --repeat-headers --no-sao --deblock -2:-2
```

Keeps more precision than HDR10 for later re-encodes. Leaves out `--hdr10-opt` (disabled at 12-bit) and Dolby Vision (refused at 12-bit). Most TVs won't decode Main12; make a 10-bit HDR10 copy for playback.

Sources: [source](https://x265.readthedocs.io/en/master/cli.html), [source](https://codecs.wiki/docs/encoders/x265)

### Dolby Vision profile 8.1 re-encode

**Goal:** HDR · **Content:** live action

```bash
dovi_tool -m 2 extract-rpu src.hevc -o RPU.bin ; x265 --input src.y4m --y4m --output out.hevc --preset slow --crf 18 --output-depth 10 --profile main10 --colorprim bt2020 --transfer smpte2084 --colormatrix bt2020nc --master-display "<from source>" --max-cll "<from source>" --dolby-vision-profile 8.1 --dolby-vision-rpu RPU.bin --vbv-bufsize 160000 --vbv-maxrate 160000 --repeat-headers
```

dovi_tool mode 2 makes the RPU profile 8.1 compatible. x265 refuses Dolby Vision without VBV and refuses 8.1 without `--master-display` (both verified on this build). The VBV numbers are placeholders: choose values your target level and devices allow. Frames must stay identical to the source.

Sources: [source](https://github.com/quietvoid/dovi_tool), [source](https://x265.readthedocs.io/en/master/cli.html)

### HDR10+ (10-bit in-encode, or post-injection)

**Goal:** HDR · **Content:** live action

```bash
hdr10plus_tool extract src.hevc -o metadata.json ; x265 <HDR10 args> --output-depth 10 --dhdr10-info metadata.json --output out.hevc  (for 8/12-bit: x265 <HDR10 args> --output out.hevc ; hdr10plus_tool inject -i out.hevc -j metadata.json -o out_hdr10plus.hevc)
```

In this build `--dhdr10-info` works only in 10-bit encodes (verified: a JSON extracted with hdr10plus_tool round-trips through x265 `-D` 10 with one 2094-40 SEI per frame). At 8/12-bit it is ignored, so inject afterwards. Either way the JSON must have one entry per encoded frame.

Sources: [source](https://github.com/quietvoid/hdr10plus_tool), [source](https://x265.readthedocs.io/en/master/cli.html)

### HLG broadcast-style

**Goal:** HDR · **Content:** live action

```bash
--preset slow --crf 18 --output-depth 10 --profile main10 --video-signal-type-preset BT2100_HLG_YCC --repeat-headers
```

The preset sets BT.2020 primaries, ARIB STD-B67 transfer, bt2020nc matrix, limited range and chroma location 2. HLG needs no mastering metadata. Some delivery specs also want `--atc-sei`/--pic-struct.

Sources: [source](https://x265.readthedocs.io/en/master/cli.html)

### Two-pass size target for streaming

**Goal:** streaming/small size · **Content:** any

```bash
--preset slow --output-depth 10 --bitrate 6000 --pass 1 --stats x265.log ; --preset slow --output-depth 10 --bitrate 6000 --pass 2 --stats x265.log --vbv-maxrate 12000 --vbv-bufsize 12000
```

Two passes hit an exact average; VBV caps peaks for streaming devices.

Sources: [source](https://x265.readthedocs.io/en/master/cli.html), [source](https://codecs.wiki/docs/encoders/x265)

### ffmpeg HDR10 via libx265

**Goal:** HDR · **Content:** live action

```bash
ffmpeg -i in.mkv -map 0:v:0 -c:v libx265 -pix_fmt yuv420p10le -preset slow -crf 18 -x265-params "colorprim=bt2020:transfer=smpte2084:colormatrix=bt2020nc:range=limited:master-display=G(13250,34500)B(7500,3000)R(34000,16000)WP(15635,16450)L(10000000,50):max-cll=1000,400:hdr10=1:hdr10-opt=1:repeat-headers=1" out.mkv
```

x265 options pass through -x265-params with ':' separators; the pixel format sets the bit depth.

Sources: [source](https://ffmpeg.org/ffmpeg-codecs.html#libx265), [source](https://codecalamity.com/encoding-uhd-4k-hdr10-videos-with-ffmpeg/)

### Fast preview encode

**Goal:** speed · **Content:** any

```bash
--preset veryfast --crf 22 --output-depth 10
```

veryfast is the fastest preset that keeps AQ and SAO; good for checking a pipeline before a long archival run.

Sources: [source](https://x265.readthedocs.io/en/master/presets.html)

## Options in detail

### Input and output

<a id="output"></a>

#### `--output` (also `-o`)

**Type:** path · **Values:** <filename> · **Default:** not stated

Where the encoded stream is written. x265 writes a raw Annex-B HEVC elementary stream, not a container; mux it with mkvmerge, MP4Box or ffmpeg afterwards.

**In Lumora:** encoders.json x265.args: `--output {out}` with ext 'hevc' (raw stream, muxed later).

<a id="output-depth"></a>

#### `--output-depth` (also `-D`)

**Type:** enum · **Values:** 8\|10\|12 · **Default:** 8 · **HDR-relevant**

Bit depth of the encoded stream, which is also the depth x265 works at internally. 10 gives Main10; 12 gives Main12 and needs a build with 12-bit support.

**Effect:** quality + (10/12-bit reduce banding) · speed - (higher depth is slower) · size ± (10-bit is often smaller at equal quality than 8-bit)

| For | Value | Why | Source |
|---|---|---|---|
| anime | `10` | The guide found 10-bit gave better results than 12-bit at the CRF values typically used for anime. | [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/) |
| HDR | `10` | HDR10 output needs a 10-bit pipeline; the article had a commenter whose encode came out 8-bit until `-D` 10 was given. | [source](https://codecalamity.com/encoding-uhd-4k-hdr10-videos-with-ffmpeg/) |

**In Lumora:** encoders.json x265.args: `--output-depth {bits}`; the HEVC 12-bit recipe (Codec.hevc12) passes 12.

**Notes:** If omitted but `--profile` is set, x265 derives the depth from the profile. Hardware decoders for Main12 are rare (most TVs, phones and streaming boxes decode Main10 at most), so 12-bit is mainly an archival/master format. Dolby Vision is refused at 12-bit (verified on this build: 'Main10 only').

<a id="input"></a>

#### `--input`

**Type:** path · **Values:** <filename> or - for stdin · **Default:** not stated

Source file: raw YUV or Y4M. `-` reads from standard input, which is how frame servers and ffmpeg pipes feed x265.

**In Lumora:** encoders.json x265.args: `--input {in}` with inputArg '-' (Lumora pipes Y4M on stdin).

<a id="y4m"></a>

#### `--y4m`

**Type:** bool · **Values:** flag · **Default:** disabled

Forces the input to be parsed as YUV4MPEG2 even if the name doesn't end in .y4m. Needed when piping Y4M through stdin.

**In Lumora:** encoders.json x265.args: `--y4m` (stdin pipe). EncodeRecipes.supportedFlags() probes `--fullhelp`, which lists it.

<a id="fps"></a>

#### `--fps`

**Type:** string · **Values:** <float\|rational> · **Default:** auto-detected if Y4M · advanced

Frame rate of raw YUV input, as a decimal or num/den (24000/1001). Y4M carries it in the header.

**Notes:** Affects rate control and VUI timing; with interlaced input it is fields per second.

<a id="input-res"></a>

#### `--input-res`

**Type:** string · **Values:** WxH · **Default:** auto-detected if Y4M · advanced

Picture size for raw YUV input. With interlaced input, give the field size.

<a id="input-depth"></a>

#### `--input-depth`

**Type:** int · **Values:** <integer> · **Default:** 8 · **HDR-relevant** · advanced

Bit depth of raw YUV input samples. Y4M declares its own depth.

**Notes:** Docs: valid 8-16, YUV only, defaults to the internal depth. Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="input-csp"></a>

#### `--input-csp`

**Type:** enum · **Values:** 0 i400 \| 1 i420 \| 2 i422 \| 3 i444 · **Default:** i420 (auto-detected if Y4M) · **HDR-relevant** · advanced

Chroma subsampling of the input. x265 does not convert chroma, so this also sets the output chroma format (4:2:2 and 4:4:4 need the matching RExt profile).

**Notes:** The online docs also list 4 nv12 and 5 nv16; the 4.3 help shows only 0-3. Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="frames"></a>

#### `--frames` (also `-f`)

**Type:** int · **Values:** <integer> · **Default:** all

Stops after encoding this many frames.

**Notes:** Also used as a hint for rate control and still-picture detection when the frame count is known.

<a id="seek"></a>

#### `--seek`

**Type:** int · **Values:** <integer> · **Default:** not stated (docs: 0) · advanced

Skips this many frames at the start of the input before encoding.

<a id="interlace"></a>

#### `--interlace` (also `--no-interlace`)

**Type:** enum · **Values:** bff\|tff (and --no-interlace) · **Default:** progressive · advanced

Declares the input as separate fields in temporal order (top- or bottom-field first). x265 then codes fields as pictures and signals it in SEI.

**Notes:** Docs also accept 0/1/2. Give field size and field rate. Deinterlacing or IVTC before encoding is usually preferable for archival. Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="field"></a>

#### `--field` (also `--no-field`)

**Type:** bool · **Values:** --field \| --no-field · **Default:** disabled · advanced

Enables field coding for interlaced input.

<a id="dither"></a>

#### `--dither`

**Type:** bool · **Values:** flag · **Default:** disabled · **HDR-relevant** · advanced

Uses a higher-quality dithered downconversion when the input has more bits than the encode (for example 16-bit input to an 8-bit encode).

**Effect:** quality + (less banding when reducing depth) · speed none · size none

**Notes:** Only matters when input depth exceeds internal depth. CLI only. Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="sar"></a>

#### `--sar`

**Type:** string · **Values:** 0..16 index or <int:int> · **Default:** 0 · advanced

Sample (pixel) aspect ratio. Needed for anamorphic sources such as DVD.

<a id="display-window"></a>

#### `--display-window`

**Type:** string · **Values:** left,top,right,bottom · **Default:** not stated · advanced

Signals a region (for example letterbox bars) that players may crop.

<a id="overscan"></a>

#### `--overscan`

**Type:** enum · **Values:** unknown, show, crop · **Default:** unknown · advanced

Tells the display whether the picture is safe to show in overscan areas.

<a id="videoformat"></a>

#### `--videoformat`

**Type:** enum · **Values:** unknown, component, pal, ntsc, secam, mac · **Default:** unknown · advanced

Signals the analog origin of the video. Purely informational.

### Rate control

<a id="scenecut-aware-qp"></a>

#### `--scenecut-aware-qp`

**Type:** enum · **Values:** 0 off \| 1 forward \| 2 backward \| 3 both · **Default:** disabled · advanced

Raises QP on frames just after (or before) a scene cut, where the eye can't see detail, to save bits.

**Effect:** quality ± (invisible when tuned well) · speed none · size -

**Notes:** Docs: only works with `--pass` 2. Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="masking-strength"></a>

#### `--masking-strength`

**Type:** list · **Values:** comma-separated window(ms),offset values · **Default:** not stated (docs: 500 ms/5, 100 ms backward) · advanced

Duration of the masking window and the QP increase used by `--scenecut-aware-qp`.

**Notes:** Docs: windows 0-2000 ms, offsets 0-20; example `--scenecut-aware-qp 1 --masking-strength 1000,8,12`. Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="scenecut-qp-config"></a>

#### `--scenecut-qp-config`

**Type:** path · **Values:** <file> · **Default:** not stated · advanced

File holding the scenecut-aware-qp mode, windows and offsets.

**Notes:** Works only with `--pass` 2. CLI only. Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="qpfile"></a>

#### `--qpfile`

**Type:** path · **Values:** <string> file: framenumber frametype [QP] · **Default:** not stated · advanced

Forces frame types (I, i, K, P, B, b) and optionally QPs for listed frames, for example to put keyframes on chapter points.

**Notes:** QPs are clamped by `--qpmin`/--qpmax. K means IDR with closed GOP, otherwise a non-IDR I. Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="bitrate"></a>

#### `--bitrate`

**Type:** int · **Values:** <integer> kbps · **Default:** 0

Average bitrate target. Alone it is one-pass ABR; with `--pass` it is multi-pass VBR.

| For | Value | Why | Source |
|---|---|---|---|
| archive | `avoid; use CRF` | The wiki says ABR is less efficient and less consistent than CRF unless a size target is required. | [source](https://codecs.wiki/docs/encoders/x265) |

<a id="qp"></a>

#### `--qp` (also `-q`)

**Type:** int · **Values:** <integer> (docs: 0..51) · **Default:** not stated · advanced

Constant QP: P frames use this QP and I/B frames are offset by `--ipratio`/--pbratio.

**Effect:** quality none · speed none · size + (wasteful vs CRF)

**Notes:** QP 0 is not lossless; use `--lossless` for that. Help text misspells `--pbratio` as 'pbration'. Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="crf"></a>

#### `--crf`

**Type:** float · **Values:** 0-51 · **Default:** 28.0

Constant rate factor: keeps a target perceptual quality and lets the bitrate vary. Lower is higher quality and bigger.

**Effect:** quality + lower · speed none · size + lower

| For | Value | Why | Source |
|---|---|---|---|
| archive | `16 (1080p) / 18 (4K) for transparency` | The wiki's transparent tier: 14/16/18 for 720p/1080p/4K. | [source](https://codecs.wiki/docs/encoders/x265) |
| anime | `18-21 on a 24-27" monitor (lowest 18)` | The anime guide picks CRF by viewing setup and says below 18 size grows fast. | [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/) |
| streaming/small size | `26 (1080p); 24 at 720p, 28 at 4K` | The wiki's medium tier (720p/1080p/4K = 24/26/28); it aims for about +6 CRF to halve the size, but this varies by source. | [source](https://codecs.wiki/docs/encoders/x265) |
| HDR | `around 20 (16-24 by content)` | The HDR article uses 20 and its commenters report 16-24. | [source](https://codecalamity.com/encoding-uhd-4k-hdr10-videos-with-ffmpeg/) |

**In Lumora:** encoders.json x265.args: `--crf {quality}`, qualityBest 12, qualityWorst 30. Lumora searches this range to hit its VMAF target.

**Notes:** x265 CRF values are not on the same scale as x264's, and quality at a given CRF also shifts with preset and bit depth. With `--level-idc`, CRF becomes VBV-constrained.

<a id="lossless"></a>

#### `--lossless` (also `--no-lossless`)

**Type:** bool · **Values:** --lossless \| --no-lossless · **Default:** disabled · advanced

Mathematically lossless mode: bypasses transform, quantization and loop filters. Rate control settings are ignored.

**Effect:** quality + (bit-exact) · speed none · size + very large

| For | Value | Why | Source |
|---|---|---|---|
| archive | `consider x264 instead` | The wiki does not recommend x265 for lossless because x264 is considerably faster without a meaningful efficiency loss. | [source](https://codecs.wiki/docs/encoders/x265) |

**Notes:** Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="crf-max"></a>

#### `--crf-max`

**Type:** float · **Values:** <float> · **Default:** 0.000000 · advanced

With CRF plus VBV, caps how high the rate factor can rise when VBV forces quality down.

**Notes:** Help and docs warn it can cause VBV underflows. Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="crf-min"></a>

#### `--crf-min`

**Type:** float · **Values:** <float> · **Default:** 0.000000 · advanced

With CRF plus VBV, sets a floor on the rate factor so easy scenes don't get excess bits.

**Notes:** Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="vbv-maxrate"></a>

#### `--vbv-maxrate`

**Type:** int · **Values:** <integer> kbit/s · **Default:** 0 · **HDR-relevant** · advanced

Peak bitrate the decoder buffer can be refilled at. With `--vbv-bufsize` it caps local bitrate.

**Effect:** quality - in hard scenes · speed none · size none

**Notes:** Needed with CRF to make 'capped CRF' for streaming/devices. VBV makes output non-deterministic across runs (unless `--const-vbv`). Dolby Vision encodes require VBV in this build: without `--vbv-bufsize`/--vbv-maxrate x265 stops with 'Dolby Vision requires VBV settings to enable HRD.' (verified locally; not stated in the online docs).

<a id="vbv-bufsize"></a>

#### `--vbv-bufsize`

**Type:** int · **Values:** <integer> kbit · **Default:** 0 · **HDR-relevant** · advanced

Size of the decoder buffer model. Turns VBV on (together with `--vbv-maxrate` for CRF).

**Notes:** Dolby Vision encodes need both VBV values (verified).

<a id="vbv-init"></a>

#### `--vbv-init`

**Type:** float · **Values:** fraction 0-1 or kbits · **Default:** 0.90 · advanced

How full the VBV buffer is assumed to be at the start.

<a id="vbv-end"></a>

#### `--vbv-end`

**Type:** float · **Values:** fraction or kbits · **Default:** 0 (disabled) · advanced

Target buffer fullness at the end of the encode, so chunks can be joined without violating VBV.

<a id="min-vbv-fullness"></a>

#### `--min-vbv-fullness`

**Type:** float · **Values:** 0-100 (percent) · **Default:** 50.00 · advanced

Lower bound rate control tries to keep the buffer above.

**Notes:** Experimental; changing it may affect conformance (docs).

<a id="max-vbv-fullness"></a>

#### `--max-vbv-fullness`

**Type:** float · **Values:** 0-100 (percent) · **Default:** 80.00 · advanced

Upper bound rate control tries to keep the buffer below.

**Notes:** Experimental (docs).

<a id="vbv-end-fr-adj"></a>

#### `--vbv-end-fr-adj`

**Type:** float · **Values:** <float> · **Default:** 0 · advanced

Point (fraction of total frames) from which QP is steered to reach `--vbv-end`.

**Notes:** Needs a known frame count.

<a id="chunk-start"></a>

#### `--chunk-start`

**Type:** int · **Values:** <integer> · **Default:** 0 (disabled) · advanced

First frame of this chunk; earlier frames are encoded for context and dropped.

**Notes:** For splitting an encode across machines. Closed GOP only (verified message: 'Chunking requires closed gop structure').

<a id="chunk-end"></a>

#### `--chunk-end`

**Type:** int · **Values:** <integer> · **Default:** 0 (disabled) · advanced

Last frame of this chunk; later frames feed the lookahead but aren't output.

**Notes:** Closed GOP only.

<a id="pass"></a>

#### `--pass`

**Type:** enum · **Values:** 1 first \| 2 last \| 3 Nth · **Default:** not stated

Multi-pass rate control: pass 1 writes stats, pass 2 uses them, pass 3 reads and rewrites them.

| For | Value | Why | Source |
|---|---|---|---|
| streaming/small size | `1 then 2 with --bitrate` | Two passes hit a file size target accurately. | [source](https://x265.readthedocs.io/en/master/cli.html) |

<a id="multi-pass-opt-analysis"></a>

#### `--multi-pass-opt-analysis` (also `--no-multi-pass-opt-analysis`)

**Type:** bool · **Values:** --[no-]multi-pass-opt-analysis · **Default:** not stated (docs: disabled) · advanced

Reuses pass-1 analysis decisions to refine pass 2.

**Notes:** Can't combine with `--analysis-save`/--analysis-load (docs). Uses `--analysis-reuse-file`.

<a id="multi-pass-opt-distortion"></a>

#### `--multi-pass-opt-distortion` (also `--no-multi-pass-opt-distortion`)

**Type:** bool · **Values:** --[no-]multi-pass-opt-distortion · **Default:** not stated (docs: disabled) · advanced

Uses per-CTU distortion from pass 1 to lower QP on high-distortion CTUs in pass 2.

<a id="vbv-live-multi-pass"></a>

#### `--vbv-live-multi-pass` (also `--no-vbv-live-multi-pass`)

**Type:** bool · **Values:** --[no-]vbv-live-multi-pass · **Default:** disabled · advanced

In pass 2, adjusts frame QP from live VBV fullness to reduce VBV violations.

**Notes:** Experimental; needs 2-pass ABR with VBV. 

<a id="stats"></a>

#### `--stats`

**Type:** path · **Values:** <filename> · **Default:** x265_2pass.log · advanced

Name of the multi-pass statistics file.

<a id="slow-firstpass"></a>

#### `--slow-firstpass` (also `--no-slow-firstpass`)

**Type:** bool · **Values:** --[no-]slow-firstpass · **Default:** enabled · advanced

When off, pass 1 uses fast 'turbo' settings; pass 2 is unaffected but its stats are less accurate.

**Effect:** quality none · speed - (when enabled) · size none

<a id="strict-cbr"></a>

#### `--strict-cbr` (also `--no-strict-cbr`)

**Type:** bool · **Values:** --[no-]strict-cbr · **Default:** disabled · advanced

Tightens ABR tolerance to keep the average within about 5% of target, at some quality cost.

<a id="sbrc"></a>

#### `--sbrc` (also `--no-sbrc`)

**Type:** bool · **Values:** --sbrc \| --no-sbrc · **Default:** disabled · advanced

Segment-based rate control built on capped CRF; plans bits per keyframe segment for streaming.

**Notes:** Added in 3.6, improved in 4.2. Forces closed GOP and min-keyint = keyint (verified messages). Experimental. Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="cutree"></a>

#### `--cutree` (also `--no-cutree`)

**Type:** bool · **Values:** --cutree \| --no-cutree · **Default:** enabled · advanced

Uses the lookahead to find blocks that many later frames reference and gives them lower QP, while unreferenced blocks get higher QP.

**Effect:** quality + usually · speed none · size -

| For | Value | Why | Source |
|---|---|---|---|
| archive | `--no-cutree` | The guide considers x265's cutree a poor version of x264's mbtree. | [source](https://silentaperture.gitlab.io/mdbook-guide/encoding/x265.html) |
| archive | `keep on` | The wiki says turning it off usually hurts and asks for evidence from those recommending it. | [source](https://codecs.wiki/docs/encoders/x265) |
| heavy grain | `off (via --tune grain)` | The grain tune disables it. | [source](https://x265.readthedocs.io/en/master/presets.html) |

**Notes:** Sources disagree directly. Analysis save/load requires it off. `--tune` psnr and zerolatency also disable it.

<a id="ipratio"></a>

#### `--ipratio`

**Type:** float · **Values:** <float> · **Default:** 1.40 · advanced

QP ratio between I and P frames; higher gives keyframes relatively more quality.

| For | Value | Why | Source |
|---|---|---|---|
| heavy grain | `1.1 (via --tune grain)` | Flattening the ratios avoids grain changing at keyframes. | [source](https://x265.readthedocs.io/en/master/presets.html) |

**Notes:** Docs say it is rarely set by hand. Listed only in `--fullhelp`, which Lumora's flag probe reads.

<a id="pbratio"></a>

#### `--pbratio`

**Type:** float · **Values:** <float> · **Default:** 1.30 · advanced

QP ratio between P and B frames.

### Psychovisual and tuning

<a id="tune"></a>

#### `--tune` (also `-t`)

**Type:** enum · **Values:** psnr, ssim, grain, zerolatency, fastdecode (help); animation also accepted · **Default:** none

Applies a content- or goal-specific adjustment on top of the preset.

| For | Value | Why | Source |
|---|---|---|---|
| heavy grain | `grain` | Disables AQ and cutree, flattens I/P/B QP ratios, turns off SAO and raises psy-rd to 4 and psy-rdoq to 10 so grain doesn't pulse. | [source](https://x265.readthedocs.io/en/master/presets.html) |
| anime | `animation` | Lowers psy-rd and aq-strength to 0.4, sets deblock 1:1 and adds 2 B-frames. | [source](https://x265.readthedocs.io/en/master/presets.html) |
| heavy grain | `avoid grain tune on slower presets` | The anime guide warns tune grain is too strong when combined with slower presets; it prefers manual psy settings. | [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/) |

**In Lumora:** Not used. encoders.json x265.tunes maps every content type to nothing; without a plan EncodeRecipes.x265Args appends the content type's base options instead, the same ones the planner always enables. `--tune` grain cost 37% XPSNR BD-rate and 51% CPU time against them, `--tune` animation 7% XPSNR (docs/encoding/tuning-x265.md).

**Notes:** `animation` is not in the 4.3 help list but is accepted (verified: it produces psy-rd 0.40, aq-strength 0.4, deblock 1:1, bframes 6 at medium). An unknown tune aborts with 'preset or tune unrecognized'. The library also contains a 'vmaf' tune name, which changed nothing in this build.

<a id="psy-rd"></a>

#### `--psy-rd` (also `--no-psy-rd`)

**Type:** float · **Values:** 0..5.0 · **Default:** 2.0

Pushes mode decisions toward keeping the source's visual energy (texture, grain, sharpness) rather than the mathematically closest smooth result.

**Effect:** quality + perceived detail · speed none · size + (higher values cost bits)

| For | Value | Why | Source |
|---|---|---|---|
| live action | `0.8-2.0` | The guide's working range; x265 generally needs higher values than x264. | [source](https://silentaperture.gitlab.io/mdbook-guide/encoding/x265.html) |
| anime | `1.0 (1.5 grainy/dark, 2.0 heavy grain)` | The anime guide scales psy-rd with how much grain or dark detail the show has. | [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/) |
| heavy grain | `4.0 (via --tune grain)` | Part of the grain tune. | [source](https://x265.readthedocs.io/en/master/presets.html) |
| streaming/small size | `lower than default` | The docs note lower bitrates call for lower psy strength or motion can judder. | [source](https://x265.readthedocs.io/en/master/cli.html) |

**In Lumora:** EncodeRecipes hevc12 option 'psy' (EncodeRecipes.x265Psy): `--psy-rd 1.0` for live action, CG, fast motion and screen content (measured -2.2% VMAF, -1.9% XPSNR BD-rate with psy-rdoq 1.0), 2.0 for anime and the grainy kinds.

**Notes:** Only has effect at `--rd` 3 and above. For 4:4:4 with psy-rd on, chroma QP offsets default to 6 (docs). Sources disagree on the anime value: tune animation uses 0.4, the anime guide 1.0, Lumora 2.0.

<a id="psy-rdoq"></a>

#### `--psy-rdoq` (also `--no-psy-rdoq`)

**Type:** float · **Values:** 0..50.0 · **Default:** 0.0 · advanced

Psychovisual bias inside RD quantization: prefers keeping coefficient energy so grain and noise stay noisy instead of being smoothed away.

**Effect:** quality + grain retention · speed none · size + (can be large)

| For | Value | Why | Source |
|---|---|---|---|
| live action | `0-2` | The guide's usual range. | [source](https://silentaperture.gitlab.io/mdbook-guide/encoding/x265.html) |
| anime | `1 (2-3 grain/CRT, 4-5 only for constant grain at CRF <16)` | Higher values cost a lot of bitrate, so the author rarely goes above 2. | [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/) |
| heavy grain | `10 (via --tune grain)` | Part of the grain tune. | [source](https://x265.readthedocs.io/en/master/presets.html) |

**In Lumora:** EncodeRecipes hevc12 option 'psy' (EncodeRecipes.x265Psy): 1.0 for live action, CG, fast motion and screen content, 1.5 for anime, 4.0 for heavy grain, low light and old anime (keeps the grain). EncodeRecipes.x265Args drops it on presets up to medium (rdoq-level 0) unless `--rdoq-level` 1 or 2 is also set; the streams were bit-identical with and without it there.

**Notes:** Only effective when `--rdoq-level` is 1 or 2. Docs warn high values can double bitrate and cause ringing. slow/slower/veryslow set 1.0.

<a id="ssim-rd"></a>

#### `--ssim-rd` (also `--no-ssim-rd`)

**Type:** bool · **Values:** --ssim-rd \| --no-ssim-rd · **Default:** disabled · advanced

Replaces the usual distortion measure in RDO with an SSIM-based one.

**Notes:** Only at `--rd` 3+. Optimizes toward a metric, which may not match what eyes prefer.

<a id="strong-intra-smoothing"></a>

#### `--strong-intra-smoothing` (also `--no-strong-intra-smoothing`)

**Type:** bool · **Values:** --strong-intra-smoothing \| --no-strong-intra-smoothing · **Default:** enabled · advanced

Smooths the reference edge used to predict 32x32 intra blocks. Reduces banding on gradients but softens sharp or grainy content.

**Effect:** quality ± (less banding vs. less sharpness) · speed none · size none

| For | Value | Why | Source |
|---|---|---|---|
| heavy grain | `--no-strong-intra-smoothing` | The guide disables it for sharp or grainy content. | [source](https://silentaperture.gitlab.io/mdbook-guide/encoding/x265.html) |
| old anime | `on (default) for blurry or soft sources` | The guide keeps it on for blurry content, since the added blur helps prevent banding. | [source](https://silentaperture.gitlab.io/mdbook-guide/encoding/x265.html) |
| anime | `on unless using --no-sao at low CRF` | The anime guide only suggests turning it off for non-anime or very low CRF. | [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/) |

**In Lumora:** EncodeRecipes hevc12 option 'nosis': `--no-strong-intra-smoothing` (visual-only, offered for every content kind). Turning it back on changed nothing measurable on live action.

**Notes:** Sources split by source sharpness rather than anime vs. live action.

<a id="aq-mode"></a>

#### `--aq-mode`

**Type:** enum · **Values:** 0 none \| 1 uniform \| 2 auto variance \| 3 auto variance + dark bias \| 4 auto variance + edges · **Default:** 2

Adaptive quantization redistributes bits inside a frame: flat areas get more, busy textured areas less, so blocking in flat areas drops.

**Effect:** quality + perceived · speed none · size ±

| For | Value | Why | Source |
|---|---|---|---|
| anime | `3` | The anime guide calls the dark-scene bias a must to prevent banding. | [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/) |
| live action | `3 or 4` | The guide usually finds 4 or 3 best. | [source](https://silentaperture.gitlab.io/mdbook-guide/encoding/x265.html) |
| archive | `2 (test 3 first)` | The wiki says 3 can bloat bitrate for little gain. | [source](https://codecs.wiki/docs/encoders/x265) |
| low light | `3` | The docs recommend 3 for 8-bit or low-bitrate 10-bit to prevent banding and blocking. | [source](https://x265.readthedocs.io/en/master/cli.html) |
| heavy grain | `0 (via --tune grain)` | The grain tune turns AQ off to keep grain uniform. | [source](https://x265.readthedocs.io/en/master/presets.html) |

**In Lumora:** EncodeRecipes hevc12 option 'aq3': `--aq-mode 3` for every kind except screen content (which keeps x265's mode 2; modes 3 and 1 cost 13-29% there). Modes 2 and 4 were measured on live action and grain and not adopted (VMAF and XPSNR disagree).

**Notes:** Sources disagree: 3/4 (guides) vs default 2 (wiki). The docs' case for mode 3 is 8-bit or low-bitrate 10-bit; at 12-bit and low CRF its benefit is less clear (not measured by any source read).

<a id="hevc-aq"></a>

#### `--hevc-aq` (also `--no-hevc-aq`)

**Type:** bool · **Values:** --hevc-aq \| --no-hevc-aq · **Default:** disabled · advanced

Alternative AQ that scales QP per CU by the minimum sub-block variance relative to the frame.

| For | Value | Why | Source |

<a id="nr-intra"></a>

### In-loop filters

<a id="deblock"></a>

#### `--deblock` (also `--no-deblock`)

**Type:** string · **Values:** tC:Beta offsets (-6..6), or --no-deblock · **Default:** enabled (0:0)

Deblocking filter that hides block edges. Negative offsets filter less and keep texture; positive filter more and smooth more.

**Effect:** quality ± (negative keeps detail, may show blocks) · speed none · size none

| For | Value | Why | Source |
|---|---|---|---|
| live action | `-3:-3 to -1:-1` | The guide's range to test for live action. | [source](https://silentaperture.gitlab.io/mdbook-guide/encoding/x265.html) |
| anime | `-2:-2 to 0:0` | The guide's range for animation. | [source](https://silentaperture.gitlab.io/mdbook-guide/encoding/x265.html) |
| anime | `0:0 or 1:1; -1:-1 for more grain/detail` | The anime guide's defaults. | [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/) |
| archive | `-1:-1 (anime) / -2:-2 (live action) at low CRF` | The wiki suggests these for lower CRF to keep grain and detail. | [source](https://codecs.wiki/docs/encoders/x265) |
| heavy grain | `-2:-2` | Fits the live-action ranges of both guides. | [source](https://silentaperture.gitlab.io/mdbook-guide/encoding/x265.html) |

**In Lumora:** EncodeRecipes hevc12 option 'deblock': `--deblock -1:-1` for anime kinds, `-2:-2` otherwise (visual-only). -1:-1 and 0:0 were measured on live action and 0:0 on anime and screen; neither saved bits.

**Notes:** In ffmpeg -x265-params write it as deblock=-1,-1 (colon is the separator there). `--tune` animation sets 1:1; fastdecode disables it.

<a id="sao"></a>

#### `--sao` (also `--no-sao`)

**Type:** bool · **Values:** --sao \| --no-sao · **Default:** enabled

Sample adaptive offset: corrects ringing and banding after deblocking by adding small per-band or per-edge offsets. Tends to smooth fine texture.

**Effect:** quality ± (fewer artifacts vs. blur) · speed none · size none

| For | Value | Why | Source |
|---|---|---|---|
| live action | `--no-sao` | The guide says no-sao is usually best and SAO blurs heavily; re-enable only for strong ringing. | [source](https://silentaperture.gitlab.io/mdbook-guide/encoding/x265.html) |
| anime | `on at CRF >= 20; --limit-sao near 18; off at <= 16` | The anime guide ties SAO to CRF. | [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/) |
| archive | `on at CRF >= 20; off below 16` | The wiki says SAO blurs at CRF 16-19 and limit-sao only partly helps. | [source](https://codecs.wiki/docs/encoders/x265) |
| heavy grain | `off (via --tune grain)` | The grain tune disables it. | [source](https://x265.readthedocs.io/en/master/presets.html) |

**In Lumora:** EncodeRecipes hevc12 option 'sao': `--no-sao` for non-anime kinds (visual-only). Turning SAO on cost 8% VMAF on live action and 45% on grain, and added banding on screen content.

**Notes:** Lumora's qualityBest 12 to 30 range spans both sides of the CRF thresholds the sources use. ultrafast/superfast have it off.

### Threading and performance

<a id="pools"></a>

#### `--pools`

**Type:** list · **Values:** <integer,...> per NUMA node; '-' none, '+' one thread per core (help); '*' all remaining (docs) · **Default:** not stated (docs: all threads on all nodes) · advanced

Sets the thread-pool size per NUMA node. On a single-socket machine one number is simply the worker-thread count.

**Effect:** quality none · speed + with more threads · size none

**In Lumora:** encoders.json x265.args: `--pools {threads}`. On Apple silicon (one NUMA node) a single number caps the worker threads, which is how Lumora limits CPU use.

**Notes:** Quote values containing + or * in the shell. Ignored if every pool-using feature (WPP, lookahead slices, threaded-me) is off.

<a id="frame-threads"></a>

#### `--frame-threads` (also `-F`)

**Type:** int · **Values:** <integer> (0 = auto) · **Default:** 0 (auto) · advanced

How many frames are encoded at once. More frame threads speed things up with a small efficiency loss because later frames can't fully use not-yet-finished references.

**Effect:** quality - slight (more threads) · speed + · size none

| For | Value | Why | Source |
|---|---|---|---|
| archive | `1 on 4 cores or fewer` | The guide found 1 gives the best quality on small CPUs and saw identical results from 2 to 16. | [source](https://kokomins.wordpress.com/2019/10/10/anime-encoding-guide-for-x265-and-why-to-never-use-flac/) |
| speed | `0 (auto)` | The wiki reports frame threading costs roughly 1-3% efficiency for a large speed gain, with no difference between 2 and 16 threads in 4.1. | [source](https://codecs.wiki/docs/encoders/x265) |

**Notes:** Sources agree the loss is small; they differ on whether 1 is worth the slowdown.

<a id="wpp"></a>

#### `--wpp` (also `--no-wpp`)

**Type:** bool · **Values:** --wpp \| --no-wpp · **Default:** enabled · advanced

Wavefront parallel processing: encodes CTU rows in a staggered order so several rows run at once. About 1% efficiency cost for several times the parallelism.

**Effect:** quality - ~1% · speed + large · size none

| For | Value | Why | Source |
|---|---|---|---|
| speed | `on (default)` | The wiki recommends keeping it on unless an external chunked encoder supplies parallelism. | [source](https://codecs.wiki/docs/encoders/x265) |

**Notes:** Disabled automatically for tiny frames or without a thread pool.

Splits each frame into this many full-width slices that are coded independently.

**Effect:** quality - (each slice resets prediction) · speed + · size none

**Notes:** Docs call it experimental and suggest it only when frame threads and WPP can't keep the CPU busy.

Computes and reports SSIM between source and reconstruction.

**Effect:** quality none · speed - (small) · size none

**Notes:** Reporting only. For a metric-optimized encode, `--tune` ssim changes encoding decisions instead.

<a id="psnr"></a>

#### `--psnr` (also `--no-psnr`)

**Type:** bool · **Values:** --psnr \| --no-psnr · **Default:** disabled · advanced

Computes and reports PSNR between source and reconstruction.

**Effect:** quality none · speed - (small) · size none

**Notes:** Reporting only. PSNR rewards blur, so pair with `--tune` psnr only for benchmarking.

<a id="hash"></a>

Writes a decoded-picture hash SEI so a decoder can check it reconstructs frames exactly.

**Effect:** quality none · speed - small · size none

**Notes:** Useful for verifying archives decode bit-exactly. Listed only in `--fullhelp`, which Lumora's flag probe reads.

**Effect:** quality none · speed - · size none

**Notes:** CLI only. Listed only in `--fullhelp`, which Lumora's flag probe reads.

**Notes:** Docs: currently can't differ from internal depth. Listed only in `--fullhelp`, which Lumora's flag probe reads.

### Other

<a id="help"></a>

#### `--help` (also `-h`)

**Type:** bool · **Values:** flag · **Default:** not stated

Prints the short option summary and exits. The short list leaves out many options.

**In Lumora:** Fallback only: EncodeRecipes.supportedFlags() asks x265 for `--fullhelp` first and reads `--help` only when that prints fewer than 20 flags (docs/encoding/tuning-x265.md).

**Notes:** In 4.3, `--help` prints about 300 lines and `--fullhelp` about 384. Flags such as `--y4m`, `--qcomp`, `--ipratio`, `--cbqpoffs`, `--zones` and `--scaling-list` only show in `--fullhelp`.

<a id="fullhelp"></a>

#### `--fullhelp`

**Type:** bool · **Values:** flag · **Default:** not stated · advanced

Prints every CLI option, including the ones hidden from `--help`, and exits.

**In Lumora:** EncodeRecipes.supportedFlags() runs `x265 --fullhelp` to learn which flags exist (230 flags on 4.3+1; `--help` lists 183). `--[no-]name` counts as both forms.

**Notes:** The captured help file for this entry is identical to `x265 --fullhelp` from 4.3+1.

<a id="version"></a>

#### `--version` (also `-V`)

**Type:** bool · **Values:** flag · **Default:** not stated

Prints the encoder version, build info (which bit depths are compiled in) and detected CPU features, then exits.

**Notes:** This Homebrew build reports '8bit+10bit+12bit', meaning one binary encodes all three depths.

<a id="nalu-file"></a>

#### `--nalu-file`

**Type:** path · **Values:** <filename> · **Default:** not stated · advanced

Text file of user SEI messages to insert, one per line as `<POC> <PREFIX> <NAL type>/<SEI type> <payload>`.

**Notes:** Docs say only prefix SEI is supported.

<a id="copy-pic"></a>

#### `--copy-pic` (also `--no-copy-pic`)

**Type:** bool · **Values:** --copy-pic \| --no-copy-pic · **Default:** enabled · advanced

Library behavior: whether x265 copies each input picture. Turning it off saves memory copies but the caller must keep buffers valid until encoded.

**Notes:** Only meaningful for API users; leave alone on the CLI.

<a id="profile"></a>

#### `--profile` (also `-P`)

**Type:** enum · **Values:** main, main10, mainstillpicture (help); docs list main12, main422-10, main444-12, -intra variants etc. · **Default:** not stated (derived from depth/chroma) · **HDR-relevant**

Enforces the limits of an HEVC profile and signals it. For 12-bit 4:2:0 use main12; for 4:2:2 10-bit main422-10.

**In Lumora:** encoders.json x265.args: `--profile {x265_profile}` (main12 for the 12-bit recipe).

**Notes:** Help only lists three names, but the docs list the full RExt set: main, main-intra, mainstillpicture/msp, main444-8, main444-intra, main444-stillpicture, main10, main10-intra, main422-10, main422-10-intra, main444-10, main444-10-intra, main12, main12-intra, main422-12, main422-12-intra, main444-12, main444-12-intra. -intra is signaled automatically when keyint is 0 or 1. CLI only.

<a id="level-idc"></a>

#### `--level-idc`

**Type:** string · **Values:** <integer\|float> e.g. 5.1 or 51 · **Default:** not stated (docs: 0 = auto) · advanced

Requests a minimum decoder level. x265 adjusts references, CTU size and VBV to stay inside it, or aborts if it can't.

**Notes:** With CRF and a level, x265 forces VBV on, and VBV makes output non-deterministic (verified message in this build). Levels 5.0+ require CTU 32 or larger.

<a id="high-tier"></a>

#### `--high-tier` (also `--no-high-tier`)

**Type:** bool · **Values:** --high-tier \| --no-high-tier · **Default:** not stated (docs: enabled) · advanced

With `--level-idc`, allows the High tier bitrate limits of that level instead of Main tier.

<a id="uhd-bd"></a>

#### `--uhd-bd`

**Type:** bool · **Values:** flag · **Default:** not stated (docs: disabled) · **HDR-relevant** · advanced

Constrains the encode toward UHD Blu-ray rules: high tier, closed GOP, no temporal layering, 1080p or 2160p only.

**Notes:** Docs call it highly experimental; it switches itself off if other options conflict. Messages in this build: 'Supported resolutions are 1920x1080 and 3840x2160', 'Turning off open GOP'.

<a id="allow-non-conformance"></a>

#### `--allow-non-conformance` (also `--no-allow-non-conformance`)

**Type:** bool · **Values:** --[no-]allow-non-conformance · **Default:** disabled · advanced

Lets x265 write a stream whose profile/level is NONE instead of aborting, for example with too many references or a tiny CTU.

**Notes:** Such streams may not play on hardware decoders. Avoid for archives meant to be playable.

<a id="ctu-info"></a>

#### `--ctu-info`

**Type:** enum · **Values:** 0, 1, 2, 4, 6 · **Default:** 0 · advanced

**Notes:** Enable only when calling x265_encoder_ctu_info; docs warn the encoder waits forever otherwise.

**Notes:** The 4.3 help prints this as `--[no-]-hrd-concat` (an extra dash, a typo); `--hrd-concat` parses (verified). Docs suggest it for every chunk except the first in chunked encoding.

<a id="x265-params"></a>

#### `-x265-params`

**Type:** string · **Values:** key=value pairs separated by ':' · **Default:** not stated

Passes any x265 option by its long name without dashes, e.g. `-x265-params crf=26:psy-rd=1`.

| For | Value | Why | Source |
|---|---|---|---|
| HDR | `colorprim=bt2020:transfer=smpte2084:colormatrix=bt2020nc:master-display=...:max-cll=...:hdr10=1:repeat-headers=1` | The HDR article passes all HDR10 signaling this way. | [source](https://codecalamity.com/encoding-uhd-4k-hdr10-videos-with-ffmpeg/) |

**Notes:** ffmpeg libx265 wrapper option (FFmpeg 9.0.2), not an x265 CLI flag. Because ':' separates options, write deblock as -1,-1 and max-cll as 1000,400. Boolean flags take =1/=0, and no- forms work as keys. Keys missing from the x265 help still work here if the library supports them; for example dhdr10-info=<json> adds HDR10+ in 10-bit encodes (verified).
